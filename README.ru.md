# Ридеры линейных штрихкодов на открытых наборах снимков

[English version](README.md)

Открытое сравнение ридеров линейных штрихкодов — EAN-13/8, UPC-A/E и Code 128 —
на 6899 символах из открытых наборов снимков с чужой разметкой и на 5840
синтетических кадрах SSCC (GS1-128) камеры над конвейером. Истина каждого
снимка, ответы каждого ридера по каждому снимку и программы, которыми они
получены, лежат здесь: любую цифру ниже можно проверить и дополнить.

| ридер | версия |
|---|---|
| **unir** — движок линейных штрихкодов [универсального ридера кодов](https://github.com/libscanner/universal-reader) (наш) | 1.2.6 |
| [zxing-cpp](https://github.com/zxing-cpp/zxing-cpp) | 3.1.1 (Python) |
| [ZBar](https://github.com/mchehab/zbar) | через pyzbar 0.1.9 |
| [OpenCV](https://opencv.org) `barcode::BarcodeDetector` | 5.0.0 |
| он же с моделью сверхразрешения WeChat | OpenCV 4.10.0 |

Коммерческие SDK не участвуют: лицензии большинства из них запрещают
публиковать замеры без согласия производителя.

## Результаты

### Точность

Прочитано символов (доля от всех символов с истиной в наборе):

| набор | символов | **unir** | zxing-cpp | ZBar | OpenCV + SR |
|---|---:|---:|---:|---:|---:|
| Artelab №1, автофокус | 214 | **211 (98,6 %)** | 193 (90,2 %) | 200 (93,5 %) | 206 (96,3 %) |
| Artelab №2, без автофокуса | 213 | **198 (93,0 %)** | 32 (15,0 %) | 34 (16,0 %) | 89 (41,8 %) |
| DEAL KAIST, EAN-13 | 3200 | **2889 (90,3 %)** | 2369 (74,0 %) | 2385 (74,5 %) | 2244 (70,1 %) |
| DEAL KAIST, EAN-8 и UPC-E | 89 | **84 (94,4 %)** | 79 (88,8 %) | 80 (89,9 %) | 62 (69,7 %) |
| SmartEngines | 3000 | **1417 (47,2 %)** | 892 (29,7 %) | 1030 (34,3 %) | 222 (7,4 %) |
| Open Food Facts * | 145 | **138 (95,2 %)** | 125 (86,2 %) | 120 (82,8 %) | 96 (66,2 %) |
| Wikimedia Commons, Code 128 | 38 | **37 (97,4 %)** | 34 (89,5 %) | 33 (86,8 %) | 0 — Code 128 не читает |
| **всего** | **6899** | **4974 (72,1 %)** | 3724 (54,0 %) | 3882 (56,3 %) | 2919 (42,3 %) |

OpenCV без модели читает 2827. Полная таблица с точностью и чужими кодами, по
символикам и «прочитано только соперником» —
[results/accuracy-color/summary.md](results/accuracy-color/summary.md).

\* см. [Оговорки](#оговорки): отбор Open Food Facts играет на руку unir и zxing-cpp.

**Ложные чтения.** На 988 опубликованных снимках без штрихкода (788 фонов
DEAL и 200 синтетических ловушек: полосы, клетка, жалюзи, растр, случайные
штрихи) unir, zxing-cpp и ZBar не выдали ничего, OpenCV — 7. То же — на 3243
кадрах производственных линий, которые мы выложить не можем. На снимках со
штрихкодами коды, которые ридер выдал, а никто другой не подтвердил
(«одиночные чужие»): unir 6, zxing-cpp 56, ZBar 80, OpenCV + SR 102. Все 6 у
unir — настоящие вторые коды на снимке, проверены глазами
(results/accuracy-color/aliens.tsv).

unir здесь читает снимок в цвете (`--color`): цвет нужен ему для одного
запасного прохода по синему каналу. В полутоне он читает 4881 (70,7 %)
вместо 4974 ([results/accuracy-gray](results/accuracy-gray/summary.md));
соперники всё равно читают по яркости и получают снимок в полутоне.

### Время

Снимки разложены на группы по тому, кто их читает, по 150 случайных в каждой:
**чёткие** — читают все четыре ридера, **средние** — unir и часть
соперников, **трудные** — только unir, **только соперники**, **никто**,
**без кода**. Все ридеры получают одни и те же байты (полутон, снимок уже в
памяти), работают в один поток в своём процессе, закреплённом за одним
производительным ядром; время — только вызов чтения; 3 круга, у снимка —
лучшее время. unir ищет один код и получает срок по-настоящему (`budget_ms` =
60, 100, 500); соперникам срок не задать — им засчитан код, прочитанный не
дольше срока.

### SSCC на конвейере (синтетика)

Открытых наборов кадров с конвейера нет, поэтому эта часть — синтетика:
этикетка GS1-128 с SSCC (156 модулей) рядом с текстом и вторым GS1-128,
номинал 2,2 пикселя на модуль, меняется одно условие за раз. Худшее
значение, при котором ридер ещё читает не меньше 90 % кадров точки; символ
почти горизонтален (±5°), 50 кадров на точку:

| условие | unir | zxing-cpp | ZBar |
|---|---|---|---|
| размер модуля | **от 0,8 px** | от 1,6 px | от 1,4 px |
| размытие σ | **до 2,6 px** | до 1,2 px | до 0,6 px |
| шум σ | **до 70** (край развёртки) | до 18 | до 3 |
| контраст печати | **до 0,04** | только полный (0,3 — 78 %) | до 0,2 |
| наклон этикетки | **до 65°** | до 45° | до 55° |
| смаз поперёк штрихов | **до 6 px** | до 2 px | только без смаза |
| JPEG | до качества 5 у всех | | |
| растискивание краски | ±0,4 модуля у всех | | |

При случайном повороте 0–360° (30 кадров на точку) unir держит те же пределы;
zxing-cpp не набирает 90 % ни в одной точке, ZBar — только около номинала.
Неверных номеров SSCC на всех 5840 кадрах: unir 0, zxing-cpp 0, ZBar 4.
OpenCV Code 128 не читает и не сравнивается.

Истина и ответ каждого ридера по каждому кадру —
[synthetic-sscc/frames](synthetic-sscc/frames), по точкам —
[synthetic-sscc/per_point.csv](synthetic-sscc/per_point.csv). Сами кадры (PNG
и JPEG, 1,3 ГБ) — в [выпуске v1](https://github.com/libscanner/barcode-1d-benchmark/releases/tag/v1).
Генератор не публикуется, кадры — да.

Сами снимки сюда не перекладываются: их нужно скачать у авторов. Раскладка

бы два источника из четырёх (zxing-cpp, ZBar, ранний прогон нашего ридера,
имя файла), коды одного источника (столбец `unsure`) не считаются ни
верными, ни чужими.

## Как повторить

```bash
pip install zxing-cpp pyzbar opencv-contrib-python pillow numpy libscanner-unir
python harness/bench.py --data data --color --out results/my-run
```

OpenCV с моделью сверхразрешения — OpenCV 4.10 в отдельном окружении
(`--python-cv4 <его python>`) и `sr.prototxt` / `sr.caffemodel` из
[WeChatCV/opencv_3rdparty](https://github.com/WeChatCV/opencv_3rdparty) (ветка
`wechat_qrcode`) в `--sr-dir`. Вызовы ридеров — в
[harness/bench.py](harness/bench.py) (`_init_reader`): каждый соперник — в
лучшем найденном нами режиме, одинаково на всех снимках.

Время: `python harness/speed.py prepare --acc results/accuracy-gray --data data --dir speed`,
затем `run` и `report`. `speed.py` меряет unir через его пакет для Python в
процессе, как и соперников; опубликованное время unir снято равноценным
зондом на C++ в процессе на той же библиотеке движка.

Без ключа лицензии unir работает 30 дней пробного периода ([libscanner.com](https://libscanner.com)).

## Оговорки

- **Отбор Open Food Facts.** На многих фото товара штрихкода нет вовсе
  (лицевая сторона, состав), поэтому из 1258 фото, скачанных 22.10.2026, в
  набор вошли 145, где код товара прочитал хотя бы один из двух ридеров —
  ранняя версия нашего движка или zxing-cpp. Это играет на руку им обоим;
  ZBar и OpenCV в отборе не участвовали.
- **Время и версия движка.** Точность — по выпуску unir 1.2.6, время — по
  unir 1.2.7: при коротком сроке он сначала читает большой снимок уменьшенным;
  без срока его ответы побайтно те же, что у 1.2.6.
- **unir мы разрабатывали, глядя на промахи на этих же наборах**, так что это
  всё равно наше «домашнее поле», хотя и с чужой разметкой. Поэтому стенд
  выложен целиком: прогоните его на своём наборе.
- Muenster BarcodeDB недоступен по ссылке авторов, BarBeR требует
  регистрации — их нет.
- SmartEngines: только снимки, где все символы — EAN/UPC или Code 128 (снимки
  Code 39, Codabar и Code 93 в набор не входят), случайные 3000 из 3960
  (`bench.py --sample 3000 --seed 1`).
